# 1. Purpose

This chapter defines the philosophy, scope, principles, and boundaries
of the PetalPath Adaptive Learning Engine. Every architectural and
implementation decision in Phase 1.5 must align with this document.

------------------------------------------------------------------------

# 2. Vision

PetalPath does not simply recommend the next lesson.

PetalPath continuously adapts each child's **learning journey** using
deterministic educational rules based on observed learning behaviour.

The objective is to provide every child with a personalized journey
while preserving a common curriculum.

------------------------------------------------------------------------

# 3. Core Philosophy

The engine is built around four continuous stages:

``` text
Observe
    ↓
Understand
    ↓
Adapt
    ↓
Update the Learning Journey
```

Every interaction teaches the engine something about the learner.

------------------------------------------------------------------------

# 4. Educational Principles

## Principle 1 --- Every child learns differently

Children may master the same concept using different modalities, speeds,
and repetition.

------------------------------------------------------------------------

## Principle 2 --- The curriculum is fixed

Educational content is authored by curriculum designers.

The engine never creates, removes, or rewrites curriculum content.

------------------------------------------------------------------------

## Principle 3 --- The roadmap is dynamic

While the curriculum remains static, the learner's roadmap changes after
every meaningful learning event.

------------------------------------------------------------------------

## Principle 4 --- Evidence before decisions

The engine records observations before making educational decisions.

It never stores "weak" or "strong" directly without supporting evidence.

------------------------------------------------------------------------

## Principle 5 --- Adaptation is continuous

Personalization happens after every session and can occur within a
session when required.

------------------------------------------------------------------------

# 5. Static Curriculum vs Dynamic Roadmap

## Static Curriculum

Defines:

-   Topics
-   Skills
-   Learning order
-   Prerequisites
-   Learning objectives

The curriculum is immutable.

------------------------------------------------------------------------

## Dynamic Roadmap

Generated by the engine.

May include:

-   Daily Practice
-   Mastery Practice
-   Recovery Activities
-   Reinforcement
-   New Topics

Every learner has a unique roadmap.

------------------------------------------------------------------------

# 6. Engine Responsibilities

The engine SHALL:

-   Observe learning behaviour
-   Build learner evidence
-   Classify learning progress
-   Adapt the roadmap
-   Generate learning sessions
-   Schedule practice and reinforcement
-   Select the next activity from the roadmap

------------------------------------------------------------------------

# 7. Non-Responsibilities

The engine SHALL NOT:

-   Create curriculum
-   Generate educational content
-   Modify lesson assets
-   Handle UI rendering
-   Manage authentication
-   Perform analytics dashboards
-   Replace educators

------------------------------------------------------------------------

# 8. Learning Modalities

Supported modalities:

1.  Video
2.  Audio (optional)
3.  Speech
4.  Writing (includes tracing)

Each modality is evaluated independently.

------------------------------------------------------------------------

# 9. Adaptation Philosophy

Adaptation occurs at three levels:

1.  Topic
2.  Modality
3.  Cognitive Effort

A child may master one modality while requiring additional practice in
another.

------------------------------------------------------------------------

# 10. Cognitive Effort

Effort is learner-relative.

Levels:

1.  Very Low
2.  Low
3.  Medium
4.  Slightly High
5.  Moderately High
6.  High
7.  Very High

The engine adjusts effort based on learner behaviour rather than fixed
lesson difficulty.

------------------------------------------------------------------------

# 11. Adaptive Recovery

When sustained struggle is detected, the engine enters Recovery Mode.

Recovery may:

-   Reduce cognitive effort
-   Change modality
-   Reinforce prerequisite concepts
-   Delay progression
-   Rebuild learner confidence

Recovery is educational scaffolding---not punishment.

------------------------------------------------------------------------

# 12. System Boundaries

Backend owns:

-   Observation
-   Evidence processing
-   Classification
-   Roadmap generation
-   Session generation
-   Adaptive constraints

Frontend owns:

-   Rendering the roadmap
-   Delivering activities
-   Displaying learner progress

No adaptive decisions exist in the frontend.

------------------------------------------------------------------------

# 13. Design Goals

-   Deterministic and explainable
-   Child-first educational experience
-   Modality-aware
-   Scalable architecture
-   Easy to validate and test
-   Extensible without machine learning

------------------------------------------------------------------------

# 14. Non-Goals

This version does not aim to:

-   Use machine learning
-   Predict long-term outcomes
-   Generate curriculum
-   Replace educational experts

------------------------------------------------------------------------

# 15. Guiding Question

The engine never asks:

> "What should the child learn next?"

Instead it asks:

> **"How should today's learning journey change based on everything we
> know about this child?"**

This principle is the foundation for every future chapter.

------------------------------------------------------------------------

